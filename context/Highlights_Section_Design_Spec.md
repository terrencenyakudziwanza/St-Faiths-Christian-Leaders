# Events Page — Engagement Enhancement Specification

## Objective

Enhance the `/events` page so it feels less like a static archive and more like a living, discoverable representation of the church.

The goal is **not** to make the page louder, busier, or more animation-heavy.

The goal is to create a stronger sense of:

- discovery
- curiosity
- movement
- context
- continuity
- meaningful interaction

The Events page should make a visitor think:

> “There are moments here worth discovering.”

rather than:

> “This is a list of church events.”

The existing Events visual identity must remain intact: bright, clean, media-first, editorial, rounded, polished, and modern.

---

# 1. Preserve the Existing Visual Direction

Do not turn the Events page into a dashboard, social-media clone, or highly animated landing page.

Continue using:

- Space Grotesk
- large rounded corners
- soft gray utility surfaces
- white/light backgrounds
- image-led compositions
- restrained typography
- low color count
- subtle shadows and borders
- soft overlays
- media as the primary visual language

Events should remain visually distinct from the cinematic Home page.

Avoid:

- full-screen hero treatments
- pinned cinematic ScrollTrigger sequences
- excessive gradients
- gold-heavy treatments
- glassmorphism everywhere
- excessive badges
- dense metadata
- complicated carousel controls
- animations that compete with the content

Engagement should primarily come from **content hierarchy and interaction**, not spectacle.

---

# 2. Give the Event Feed a Sense of Discovery

The existing event feed should remain the primary content experience, but individual events should no longer feel visually identical in importance.

Introduce subtle contextual indicators where appropriate:

- `New`
- `Featured`
- `This Week`
- `Live`
- media counts such as `12 photos · 3 videos`

These should be visually understated.

Use small pills, labels, or metadata rather than large banners.

The purpose is to help the visitor understand the feed at a glance and give certain events a little more visual significance.

Do not add these indicators mechanically to every event.

Only show them when the information is genuinely useful.

---

# 3. Make Event Cards More Interactive

Event cards should feel slightly more alive when the user interacts with them.

On desktop hover:

- image layers should respond with a very subtle scale or positional shift
- a soft overlay may appear
- a play/media indicator can become more visible
- useful media information can gently appear
- the card can lift very slightly

For example, an event could reveal:

`▶ 3 videos · 18 photos`

or another relevant media summary.

The interaction should feel like **progressive disclosure**, not a dramatic animation.

The card should still look excellent when completely static.

On mobile, where hover does not exist, useful metadata should simply remain visible or appear naturally after interaction.

---

# 4. Strengthen the Highlights Section

The Highlights section should sit between the main Events feed and Latest Shorts.

Its purpose is to surface a small collection of memorable moments from recent events.

It should remain deliberately smaller in visual importance than the primary event feed.

### Feel

Highlights should feel:

- editorial
- intimate
- curated
- media-driven
- calm
- slightly immersive
- human

It should not become a second hero section.

### Composition

Use an editorial composition rather than a uniform card grid:

- one slightly more prominent moment
- several supporting moments
- varied image proportions
- generous spacing
- soft rounded media frames

The larger moment should feel important without feeling like a homepage hero.

### Content

Favor moments such as:

- preaching
- prayer
- worship
- congregation
- celebration
- a particularly strong event photograph
- a short video moment

Avoid making Highlights simply a larger version of Shorts.

Highlights are about **meaning and context**.

Shorts are about **speed and discovery**.

### Context

Where appropriate, attach very small contextual information to a highlight:

> A moment of prayer during Sunday Service

> Sunday Service · 14 Sep

Do not caption every item.

A little context should make the media feel like a story rather than a gallery.

---

# 5. Make the Event Modal Lead Somewhere

The existing event modal is already one of the most feature-rich parts of the Events experience.

Use it as a gateway rather than a dead end.

When someone finishes exploring an event, provide a subtle continuation mechanism.

For example:

**Continue exploring**

- Previous event
- Next event

or:

**You might also like**

- one or two related events

The visitor should be able to continue discovering content without having to close the modal and restart their search.

Keep this understated.

The modal should still prioritize the event's own media and information.

---

# 6. Create a Natural Discovery Loop

The Events page should gradually guide visitors through different types of content.

The intended rhythm is:

**Browse Events**  
↓  
**Discover an interesting event**  
↓  
**Open the event**  
↓  
**Explore its photos/videos**  
↓  
**Continue to another event or related content**  
↓  
**Discover Highlights**  
↓  
**Watch Shorts**  
↓  
**See what is coming next**

The page should feel like a continuous exploration experience rather than several unrelated sections stacked vertically.

---

# 7. Add an Upcoming / Coming Up Element

The page should represent both the church's history and its current life.

Introduce a restrained **Upcoming** or **Coming Up** element for future events.

It should communicate something like:

> **Coming Up**

> Sunday Worship  
> 12 October · 09:00

with a simple action such as:

> View details →

This should not dominate the page.

It should feel like a small bridge between the archived event content and what is happening next.

The broader experience becomes:

**What happened → What is happening → What is coming**

---

# 8. Give the Page a Stronger Sense of Time

The event feed should communicate recency naturally.

Use subtle date/context treatments such as:

- This week
- Last week
- Earlier this month
- Recent

Do not necessarily split the entire feed into large sections.

The existing chronological structure can remain.

The purpose is simply to make the feed feel alive and current rather than like an undifferentiated archive.

---

# 9. Improve Sharing

Sharing should be extremely easy from event and media views.

Where technically appropriate, support:

- native device sharing
- WhatsApp sharing
- copy link

Sharing should ideally preserve the specific destination.

If someone shares a particular event or media item, the link should lead directly to that event/media context rather than simply sending someone to the generic `/events` page.

The share experience should remain visually minimal.

Do not add large social-media UI around it.

---

# 10. Introduce the Idea of “Moments”

Some content can be described as a moment rather than simply an event.

Possible conceptual labels include:

- Worship
- Prayer
- The Word
- Community
- Celebration
- Moments

These do not necessarily need to become additional filters.

They can be used sparingly within Highlights or media metadata to give the content more emotional/contextual meaning.

The goal is to communicate that the site contains **experiences and moments**, not merely event records.

---

# 11. Add Occasional Discovery Content

Very occasionally, the page can surface something unexpected.

Examples:

> **From the archive**  
> A memorable moment from six months ago.

or:

> **Did you know?**  
> 8 services were held this month.

This should be rare and carefully designed.

Do not turn it into a statistics dashboard.

The purpose is to occasionally interrupt the predictable chronological feed with something interesting.

The content should feel curated rather than algorithmically generated.

---

# 12. Improve Search as a Discovery Tool

The existing advanced search should remain visually simple:

- search input
- leader filter
- event type
- date filter

However, search behavior should feel intuitive.

The primary search field should allow visitors to search naturally for things such as:

- event names
- leaders
- topics
- meaningful words appearing in event content

For example:

`Pastor John`

`Revival`

`Prayer`

`September`

The user should not need to understand which filter corresponds to their query.

Results should update naturally and immediately where possible.

The search experience should feel like **finding something**, not filling out a form.

---

# 13. Avoid Turning Engagement Into “Popularity”

Do not overuse social metrics.

Likes, views, or shares can be shown where they already make sense, particularly inside the event/media experience.

However, the Events page should not become dominated by:

- like counts
- view counts
- popularity rankings
- trending badges
- follower-style statistics

The philosophy should be:

> “This moment mattered.”

not:

> “This content has the most engagement.”

That distinction is important to the identity of the church website.

---

# 14. Motion Guidelines

All new engagement interactions should follow the existing Events motion language.

Motion should be:

- subtle
- smooth
- responsive
- purposeful
- short
- content-supporting

Good examples:

- gentle image scale on hover
- tiny card lift
- soft overlay reveal
- fade/slide of contextual metadata
- restrained section reveal
- smooth modal continuation
- subtle media transitions

Avoid:

- pinned scrolling sections
- large image choreography
- aggressive parallax
- dramatic text splitting
- full-screen transitions
- long entrance animations
- constant movement

The Events page should feel **alive**, not animated for its own sake.

---

# 15. Responsive Experience

### Desktop

Take advantage of:

- editorial media compositions
- wider event cards
- richer hover states
- subtle secondary metadata
- larger Highlights compositions
- side-by-side modal layouts

Maintain generous whitespace.

### Tablet

Simplify compositions while preserving the editorial hierarchy.

Reduce the number of simultaneously visible supporting elements where necessary.

### Mobile

Prioritize:

- readable event cards
- touch-friendly controls
- swipe/scroll-friendly media
- obvious tap targets
- compact metadata
- straightforward navigation

Do not force complex desktop compositions onto mobile.

For Highlights, a simplified stacked composition or horizontal touch-friendly rail is acceptable if it feels natural.

Avoid introducing complicated carousel arrows or pagination controls simply to preserve a desktop layout.

---

# 16. Relationship Between Events, Highlights, and Shorts

These three experiences must feel deliberately different.

### Events

**Purpose:** Discover and explore church events.

Feel:

- informative
- editorial
- substantial
- chronological
- media-rich

### Highlights

**Purpose:** Discover meaningful moments.

Feel:

- curated
- intimate
- contextual
- spacious
- editorial

### Shorts

**Purpose:** Quickly discover engaging short-form media.

Feel:

- lightweight
- fast
- social
- portrait-oriented
- casual

The three sections should create visual rhythm without becoming visually inconsistent.

Most importantly:

**Highlights must not become larger Shorts.**

---

# 17. Overall Experience

The final Events page should feel like a living archive of the church.

A visitor should be able to:

1. Quickly find an event.
2. Notice something visually interesting.
3. Open it.
4. Explore its media.
5. Understand the context around it.
6. Continue discovering related content.
7. Encounter a meaningful Highlight.
8. Watch a few Shorts.
9. See what is coming next.
10. Easily share something they found meaningful.

The experience should encourage exploration without aggressively demanding attention.

---

# 18. Priority Order

Implement the enhancements in roughly this order:

### Priority 1 — Event discovery
- richer event card interaction
- subtle contextual states
- better media metadata
- improved search behavior

### Priority 2 — Highlights
- editorial Highlights section
- contextual moment descriptions
- carefully curated visual hierarchy

### Priority 3 — Modal continuation
- related events
- previous/next navigation
- improved continuation after media exploration

### Priority 4 — Sharing
- native share
- WhatsApp
- copy link
- deep links to specific event/media content where practical

### Priority 5 — Upcoming
- restrained upcoming event element
- connection between past events and future events

### Priority 6 — Secondary discovery
- occasional archive moments
- occasional contextual statistics/facts
- “Moments” style contextual labels

Do not implement all secondary ideas if they make the page feel crowded.

---

# Final Design Principle

The Events page should become **more engaging through better curation, context, interaction, and discovery—not through visual noise.**

Every addition should pass this test:

> **Does this help the visitor discover, understand, remember, or share something meaningful?**

If not, leave it out.

The final impression should remain:

> **Clean. Modern. Alive. Human.**

The page should feel like you are exploring the life of the church—not browsing a database of events.
